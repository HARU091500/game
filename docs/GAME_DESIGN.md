# LAST STORAGE — MVP ゲーム仕様

## 開発方針

会社の PC には Unreal Engine、Visual Studio、その他の開発ツールをインストールしません。現在の作業は Codex Cloud と GitHub で行い、仕様書、C++ のデータと計算、クラウドで実行可能なテストを蓄積します。UE の実行、UE 用ビルド、Blueprint、3D 配置、操作感と映像の確認は、後で自宅 PC で行います。

エンジンは **Unreal Engine 5、正確なバージョンは未確定**です。既存の UE 向け C++ プラグインと Editor スクリプトは準備段階で、UE 上での動作確認は済んでいません。クラウドのテスト成功は、UE のビルドやゲーム完成を意味しません。

## 体験と最小範囲

プレイヤーは倉庫オークションで中身の価値を予想して落札し、室内を一人称で探索します。品物を集め、鑑定して売却し、手元の資金を増やすゲームです。

| 項目 | 最初の MVP |
|---|---|
| プラットフォーム | Windows PC。Steam 販売を長期目標にする |
| 視点・人数 | 一人称 3D、シングルプレイのみ |
| 倉庫 | 1室。仮レイアウトは内寸12×10×3 m |
| アイテム | 10種類。見た目は当初キューブなどの仮素材 |
| 操作 | 公式 First Person テンプレートの移動・視点。Eで対象を調査 |
| 経済 | 落札費用、収集した所持品、鑑定額、売却、所持金 |
| 構成 | 判定と状態変更は C++。配置、見た目、表示、音は Blueprint / Editor |

マルチプレイ、巨大マップ、複雑な AI、実在ブランド品、ネットサービス連携は最初の範囲に含めません。

## 1回のプレイの流れ

1. 所持金を確認して、倉庫1室のオークションに参加する。
2. 落札可能な金額内で入札し、落札した時だけ所持金から代金を引く。
3. 倉庫に入り、アイテムを調査して収集する。
4. 所持品を鑑定し、売却額を確認する。
5. 売却すると所持金が増え、対象が所持品からなくなる。
6. 売上と落札費用を確認して、今回の利益を把握する。

これは MVP 全体の仕様です。現在、標準C++による1室の進行とテキスト試遊がありますが、これらが UE 上で一通り遊べる状態ではありません。

## オークションと資金の暫定ルール

- 初期所持金は **1000クレジットを仮値**とします。バランス調整前の仕様であり、経済コアは呼び出し側から渡された初期残高を扱います。
- 1クレジットを最小単位とし、金額は非負の64ビット符号付き整数です。小数、負債、現実のお金は扱いません。
- 入札額は所持金を超えません。落札失敗時は所持金を変えません。
- 最初は1室分のシンプルな進行にし、入札相手の複雑な AI や価格相場のシミュレーションは作りません。
- 開始価格、入札幅、各品物の価格は未調整です。売上が必ず落札費用を上回るとは定めません。

オークションの状態管理は `WarehouseSession`、支払いと売却の計算は既存の経済コアが担当します。

### クラウドで検証する1室の進行

既存の経済コアを呼ぶ標準C++の `WarehouseSession` とテキスト試遊を実装しています。最初のオークションはプレイヤーの入札・落札確定・落選を手動で指定する進行サンプルとし、NPCの競りやタイマーは含めません。

- 入札額は開始価格以上かつ直前の入札より大きい整数。所持金を超える入札は拒否します。入札だけでは所持金を引きません。
- 落札確定時に一度だけ引き落とし、倉庫に入れる状態にします。落選時は支払わず終了します。入札なしの確定や二重確定は拒否します。
- 落札前・落選後は収集・鑑定・売却できません。
- 個体を収集した後だけ鑑定できます。サンプルの鑑定額は入力データの固定値を使い、試遊コマンドから任意の金額を指定できません。
- 最初の終了条件は、倉庫内の全品を収集・売却して `finish` を実行することです。途中撤退・廃棄・次の倉庫への移動は後の仕様です。
- 収支は売上・落札費用・利益を分け、利益は売上−落札費用とします。失敗した操作は所持金・個体・進行状態を変えません。

サンプル価格は `Data/mvp_economy.json`、名前と説明は既存の配置JSONから取り込みます。初期所持金1000、開始価格100、自動デモの入札300、10品合計1750はバランス調整前の仮値です。テキスト試遊はUEや3Dの実行を代替せず、同じC++進行を確かめるためのものです。

## アイテム10種類

種類 ID は既存の `Tools/Unreal/warehouse_layout.json` に合わせます。初期配置では各1個、合計10個です。

| 種類 ID | 表示名 |
|---|---|
| `radio` | 古いラジオ |
| `camera` | フィルムカメラ |
| `clock` | 置き時計 |
| `toolbox` | 工具箱 |
| `record` | レコード |
| `vase` | 花瓶 |
| `console` | レトロゲーム機 |
| `watch` | 腕時計 |
| `painting` | 額入りの絵 |
| `chest` | 小さな木箱 |

種類の定義には種類 ID、名前、説明、基準価値を持たせます。個々の所持品には別の **個体 ID**、種類 ID、所有状態、鑑定状態、鑑定額を持たせます。同じ種類を将来2個置く場合も、個体 ID は別です。IDには小文字ASCII英数字、`_`、`-`を使い、空や予約語`none`を避けます。個体 ID は同一セッションで再利用しません。種類 ID をそのまま個体 ID の代わりに使いません。

価格の正本と仮レイアウトの役割は分けます。配置 JSON にある説明や位置だけから、鑑定済みかどうかや売却額を決めません。

## 調査・収集・鑑定の区別

**調査**では、画面中央から届く品物の名前と説明を見ます。調査しただけでは、所有権、鑑定額、所持金を変えません。既存の E キー調査用プラグインはこの段階のコードです。

**収集**では、倉庫内の個体をプレイヤーの所持品へ移します。同じ個体が倉庫と所持品の両方に残らないようにします。初回の売却テストでは、経済コアの取得APIで所持品データを用意します。3D Actor の回収処理は後の段階です。

**鑑定**では、所持品に鑑定済み状態と整数の鑑定額を記録します。経済コアは外から渡された鑑定額を記録するAPIだけを用意し、最初は真贋判定、品質倍率、ランダムな査定、鑑定費用を導入しません。鑑定の操作・演出・結果生成は後の作業です。

売却前の所有中アイテムは再鑑定による金額の更新を許可します。売却済みの個体は再鑑定できません。

## 最初の売却ルール

以下は実装を小さくするための **暫定 MVP 方針**です。

- 所持している、鑑定済みの個体だけを売れます。未鑑定品の売却は失敗します。
- 売却額は、その個体に記録された鑑定額をそのまま使います。手数料や倍率はありません。
- 鑑定額0は有効です。売却しても所持金は増えませんが、対象は所持品からなくなります。
- 成功時は所持金への加算と所持品からの除去を一つの処理で行います。
- 所有状態は `InInventory` と `Sold` で区別します。売却後は所持品件数から除外しますが、同一セッション内の個体記録は残します。
- 存在しない個体、未鑑定、負の金額、不正なデータ、残高の上限超過などは失敗にし、所持金も所持品も変更しません。
- 売却済みの同じ個体への再要求は `AlreadySold` として失敗します。売却済み ID の再取得も拒否し、同じ個体を何度も換金できないようにします。永続的な売却履歴やセーブ間の重複防止は別の作業です。
- 64ビット整数の最大値を超える加算は事前に検出し、整数の巻き戻りや負残高を発生させません。

例：所持金1000、鑑定額250のラジオを売ると、所持金1250になり、そのラジオ個体が所持品からなくなります。同じ個体を再度売ろうとしても1250のままです。

## 周回後の目標

最初の1室・10種類を再利用して、収集図鑑・累計と最高利益・クリア数・称号を追加します。図鑑完成と黒字クリア後に銅契約、銅達成で銀、銀達成で金を解放します。契約は実際の落札費用と利益を確認し、達成しても追加の現金報酬は付けません。

進捗のC++と4周の自動試遊は用意しています。MVPのUE接続や3D制作の完了とは別です。条件・仮価格・保存未対応の範囲は [ENDGAME.md](ENDGAME.md) を参照してください。

## MVP の完了条件

クラウドでは、仕様書、データの整合性、売却の正常系と失敗時の不変条件を確認します。UE が不要な C++ テストが通ったかを記録します。

自宅 PC では、UE の正確なバージョンを記録し、UE のビルド、倉庫配置、移動、調査、収集、鑑定、売却、所持金表示を実行して確認します。保存して開き直した状態や Windows パッケージも確認して初めて、該当項目を完了とします。セーブ機能の実装前に、プレイ進行が再起動後も保持されるとは扱いません。

素材を追加する場合は、無料か商用利用可能なものに限り、取得元とライセンスを `ASSET_REGISTER.md` に記録します。現在の仮素材参照とライセンス確認の残項目も同文書に記録しています。
