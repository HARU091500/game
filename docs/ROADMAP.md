## 今回の実装単位

**1室を落札し、10品を収集・鑑定・売却して収支を確認する進行**を実装しました。既存の売却ロジックを再利用し、対話式と自動のテキスト試遊を用意しています。

ゲーム進行はSessionが所有し、落札確定前に倉庫へアクセスしたり、同じ個体を再取得・再売却したりできないようにします。売却済みの記録はセッション中に保持します。3D Actorとの連動、鑑定の演出、UE UIは含めません。

開始価格100・初期資金1000・仮価格をデータに置き、手動の落札／落選と全品売却での終了を暫定仕様にします。未鑑定品は売却不可、手数料なし、鑑定額0は有効です。価格バランスや品質倍率を同時に追加せず、純粋な C++ コアの成功を UE への組み込み成功と読み替えません。

クラウドで次に進める候補は、セーブと復元の仕様・テストです。UE側は正確なバージョンと自宅PCの環境が用意できた時点で接続します。

周回目標の詳細と実測値は [ENDGAME.md](ENDGAME.md) にあります。基礎実装を先に検証しても、MVPの1室を拡大したり、新しい3Dアセットやマルチプレイを追加したりはしません。

## Git と作業の進め方

- 仕様変更 → 小さな実装 → 実行可能なテスト → 変更ファイルと結果の報告、の順で進めます。
- ソース、文書、設定、保存したアセットは Git 管理します。生成キャッシュやビルド出力は追加しません。大きな UE バイナリアセットは既存の Git LFS 設定を使用します。
- GitHub 上で共有するにはコミット・プッシュが必要です。クラウド内の未コミットファイルが別 PC へ自動で共有されたとは扱いません。
- 各変更では、成功・失敗・未実行を分けます。特に UE 用コードは、対象エンジン版と UE ビルドの実施状況を明記します。
- 新しい素材を追加する時は、取得元・商用利用条件・再配布条件を確認します。
